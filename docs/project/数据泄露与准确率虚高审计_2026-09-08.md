## 1. 首要发现：测试依赖整批 query 的 BatchNorm 统计

**确定存在，且已实测出很强的批次依赖。** `maml_train_pic.py:974` 的 `test()` 加载权重后没有改变默认 train 模式；`fast_adapt()` 在第 600 行把整个 query batch 一起送入模型。当前两数据集均为 5-way、每类 15 query，因此预测一张未知图时还用到了其余 74 张图的 BN 统计。`maml_model.py` 中 LSK 的多处 `BatchNorm2d` 在这个模式下使用当前 batch 的均值与方差。

`l2l_shim.py:120–130` 的 clone 只复制参数，不复制 buffers。实际 query 前向还改变了基础模型的 27 个 BN buffers。需要注意：当前 train-mode BN 前向主要使用即时 batch 统计，不能仅凭 buffers 共享就断言过去 query 标签被学进模型，或把它当成另一项已量化的涨分原因。

### 数值复核

- 权重：`model_save/PU-LSK-GCNet-GGMRW-9state-seed38-new_best`，严格加载到当前默认 LSK-lite + GCNet 结构。
- 数据：PU 当前 seed38 的 target-test；独立采样 seed `20260908`；10 个配对的 5-way 1-shot 15-query episode；每个 support 适应 10 步。
- 保持每个 episode 的 support、适应后参数及 75 张 query 完全相同，仅将 query 从整批改成逐张前向。
- 整批 query：**91.73%**；逐张 query：**35.60%**；750 次预测中 **473 次**类别判断变化。
- 每个 episode 的最大 logit 变化为 14.20–28.00；query 前向改变基础模型 27 个 BN buffers。

这是一项机制诊断，证明当前分数强烈依赖测试批次组成。**35.60% 不是正确修复后重新训练的准确率，也不能据此声称现有结果精确虚高 56.13 个百分点。** 逐张 train-mode BN 同样改变了原训练分布。若研究明确允许整批无标签 query 联合参与预测，这是 transductive 评测；若目标是逐样本诊断，或对比方法使用 support-only/inductive 评测，则当前结果不可直接公平比较。

应优先统一训练与评测的 BN 协议：每个 clone 独立 buffers、统计更新仅使用允许的 source/support，query 冻结读取；或者所有对比明确统一采用 query-batch transductive 协议。不能只在旧模型上加一行 `eval()` 就把所得分数视为修复后的正式实验结果。

## 2. 两个会造成任务难度误判的边界

1. **PU 每类只选一只轴承，训练和测试沿用同一组轴承编号，仅更换工况。** `config_pu.py:23–36` 将九个状态一一映射到九只轴承，`pu_dataset.py:181–205` 在 source/target 中读取相同编号。模型可能利用个体特征；该数据设计不能区分状态特征与个体特征。它能检验同批轴承跨工况识别，不能支撑未见轴承、未见故障类别的泛化结论。此项是任务边界，尚未量化个体特征贡献，不能直接判定当前跨工况分数造假。
2. **目标域有标签 validation 逐轮参与选模。** `maml_train_pic.py:750–751、819–826、910–915` 每轮采样目标 validation episode，按准确率挑 `_best`，还可能进行满分确认早停。它不是目标测试标签直接进入梯度，但相对于完全未接触目标验证标签的评测获得了额外信息。当前协议应明确为目标域验证辅助的跨工况评测，不能称严格 target-unseen；500 轮随机验证的最高值也不能代替最终 test。

以上两个边界只有在论文结论或对比协议超出它们时构成严重误导，不应一概归为程序错误。

## 3. 数据和标签检查结果

通过当前预处理代码复现随机窗口位置并逐像素核对磁盘 PNG：PU 当前九类、四工况共 **1440/1440** 张一致；CWRU 全部 **1600/1600** 张一致。两者选用的完整振动数组未发现相同 SHA-256，各自图片集合也未发现像素完全重复。

- 源工况与目标工况配置分离；主数据加载器的 train/validation/test 选择对应独立图片集合。
- `TaskDataset` 在同一 episode 内无放回采样后分 support/query，没有把同一张图同时放进两边。
- 测试适应损失只使用 support 标签；query 标签用于 loss/accuracy 计分，没有 query-loss 的 adapt 或 optimizer step。验证也没有 outer backward；GGM-RW 只使用 source 训练任务。
- accuracy 计算是 query 的 argmax 命中数除以 query 数量，未发现把训练准确率误报为测试准确率的主链路错误。
- CWRU 目标 validation/test 从原始信号前后半段分别生成，当前目标域切片彼此无重叠。

**PU 存在小范围原始采样点重叠，但当前证据不支持将它视为严重虚高的主要解释。** `sample_starts()` 的随机抖动没有强制窗口互斥；图片随后随机分 validation/test。当前 seed38 有 1 对跨 validation/test 窗口，重叠 119/4096 点（2.91%），涉及 180 张 test 中的 1 张；test 内有 6 对部分重叠窗口，可能在不同任务中跨 support/query。seed3/24 分别有 8 对跨 validation/test 窗口，涉及各自 8/180 张 test；这些跨集合窗口的重叠最多 609/4096 点（14.87%）。这不是“PNG 不重复所以信号完全独立”，但也不是大面积训练/测试复制。

CWRU 有 54 对重叠窗口集中在源域 `C0_1797rpm/IR_014`，其信号较短；当前目标 C3 没有这个问题，不能把源域内部重叠直接当成目标测试泄露。

PU 的 validation/test 来自同一条 trial，所有工况沿用同一组物理轴承；即使消除窗口重叠，也不会自动成为独立轴承评测。

## 4. 排除出本轮重点的事项

当前仍有 validation 在 outer update 前计算、checkpoint 在 update 后保存的问题，但没有证据表明它系统性造成严重测试涨分，本轮不把它列成核心发现。旧 `test_seed_search.py` 的择优测试 seed 做法若用于正式报告会带来选择偏差，但它不被主入口调用，且其旧 episode 解包与当前接口不兼容；没有证据将当前正式结果归因于该脚本。
