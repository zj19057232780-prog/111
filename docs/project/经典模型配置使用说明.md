# 经典模型配置使用说明

> 2026-09-10更新：按用户要求，当前PU/CWRU默认已改为普通`resnet18`，源域从零监督训练、目标直接预测，无支持集微调。详见《普通ResNet18配置使用说明.md》。下文resnet18_ft仅为保留的历史可选接口，TL-WDCNN流程不变。

## 1. 只修改配置切换模型

PU修改`IFMAML-master/config_pu.py`中的PU_CONFIG；CWRU修改`IFMAML-master/config_cwru.py`中的CWRU_CONFIG。

```python
'method': 'protonet',
'run_mode': 'train_test',
```

| method | 行为 |
|---|---|
| configured_maml | 原项目配置，包括可选LSK-lite、GCNet、GGM-RW；保持既有模型结构和保存名兼容 |
| maml | 标准二阶MAML，强制CNN4，无增强与任务加权 |
| protonet | CNN4＋类别均值原型，平方欧氏距离＋交叉熵 |
| matchingnet | CNN4＋支持集匹配，默认启用支持BiLSTM和查询注意力LSTM完整上下文嵌入，负对数似然损失 |
| relationnet | CNN4空间特征＋关系网络，类内特征求和、sigmoid关系分数、one-hot均方误差 |
| resnet18 | 普通ResNet18，全类别源域监督训练＋目标直接分类，无微调 |
| resnet18_ft | 单通道STFT ResNet18，源域监督预训练＋每任务support微调 |
| tl_wdcnn | 一维原始振动WDCNN，源域监督预训练＋每任务support微调 |

method原有选择保留。选择四个经典选项时，解析器自动覆盖backbone=cnn4及frequency_module/denoise_module/attention_module/task_weighting_mode=none，不需要手工反复关闭下方参数。重新切回configured_maml时，重新启动进程即可使用配置文件中的原始设置。

run_mode：train仅训练并保存best；test仅加载best测试；train_test训练后加载best测试。新模型必须先训练，不能读取另一算法的权重。

## 2. 运行入口

工作目录为IFMAML-master，在已安装PyTorch的ifmaml2环境运行：

```powershell
# PU，直接运行时采用config_pu.py中的run_mode
python maml_train_pic.py

# CWRU，直接运行时采用config_cwru.py中的run_mode
python run_cwru_maml.py
```

PyCharm也可以直接运行这两个文件，工作目录设为IFMAML-master。历史test_only.py/test_only_reproducible.py不属于本次统一接口，请使用上面的主入口并设置run_mode=test。

显式命令行动作优先于run_mode：`--train`只训练，`--test`只测试，`--train --test`训练后测试。`--quick`（或QUICK_TEST=True）会缩小运行规模，仅用于调试。CWRU单独`--preprocess`不触发配置中的训练动作。

## 3. 保存与实验参数

经典模型自动生成含数据集、算法、目标工况、way/shot、seed和配置短哈希的model_name，并保存在model_save目录。哈希区分源工况、类别、编码器维度及FCE等设置；名称控制长度以适应Windows路径。显式`--model_path`可以覆盖自动路径，需自行保证名称唯一。

最佳权重仍为`<model_name>_best`。同时保存`<model_name>_best.config.json`记录展开配置；测试会拒绝元信息中的算法与当前method不一致的权重。旧的configured_maml权重无元信息时仍允许加载。

n_way、k_shot、q_query、source_condition、target_condition、seed、epochs、outer_lr等继续在原位置修改。经典metric方法不使用inner_lr/adaptation_steps/test_inner_steps，也不进行GGM pilot。MAML沿用现有二阶适配流程。结果沿用原有训练曲线、预测CSV、混淆矩阵与t-SNE输出开关。

MatchingNet特有：matching_fce=True，matching_fce_steps=5。False表示简化版，不能在论文中声称使用完整FCE。FCE会显著增加参数量；四模型共享CNN4编码器不意味着整体参数量相等。

RelationNet特有：relation_hidden_size=8。度量温度metric_temperature=1.0作用于ProtoNet距离和MatchingNet注意力，不用于RelationNet。

## 4. 实现与验证边界

本次为项目内实现，不是逐行复制GitHub原作者代码。算法依据前轮已确认的经典方法，使用当前CNN4统一编码器；RelationNet采用适应64×64输入的空间关系头（末端自适应池化），应在论文中说明统一骨干和实现差异。MatchingNet保留FCE选项。评测保留现有批量query BatchNorm约定，不切换成单张推断。

2026-09-09验证：
- 三个metric模型的1/5-shot输出、所有可训练参数的有限梯度、参数不被support内循环更新、保存回读一致性。
- PU和CWRU各四模型，共8条真实数据1-epoch训练→best保存→新实例加载→测试链路。使用3-way、1-shot、2-query、8隐藏通道和两个测试episode限制成本。
- 三个metric模型在实际64隐藏通道、5-way、5-shot、15-query设置下前向/反向通过。
- 两个入口无命令行动作参数时的config-only test分派通过。
- 配置解析幂等性和无效method拒绝通过。
