## 1. 实验目标

本轮只回答以下问题：

1. 当前全部模块能否完成前向、二阶 MAML 反向、保存和独立测试。
2. LSK-lite 相对 CNN4 是否稳定有效。
3. GFNet-lite、ARSM、EMA-lite、GCNet 各自相对直接父模型是否有稳定增益。
4. GFNet-lite 与 ARSM、EMA-lite、GCNet 之间是协同、无关还是冲突。
5. PU 上得到的模块排序能否在 CWRU 上复现。
6. 哪些模块应进入后续主线，哪些只保留为负结果消融。

本轮不加入可学习学习率、课程任务、域对抗、自适应 STFT 等新模块，也不同时调整 STFT 参数。先把现有模块的真实贡献重新建立清楚。

---

## 2. 当前模型和模块插入顺序

当前 LSK 分支的实际顺序为：

```text
STFT 灰度图
  -> Conv stem
  -> LSK-lite stages
  -> GFNet-lite（可选）
  -> ARSM（可选）
  -> EMA-lite / GCNet（二选一，可选）
  -> Global Average Pooling
  -> Linear classifier
  -> MAML inner/outer loop
```

CNN4 是独立骨干。当前代码不会把 GFNet、ARSM、EMA 或 GCNet 接入 CNN4，因此这些模块只在 LSK-lite 分支上验证。

### 3.2 四个必须先控制的评测风险

1. **固定数据划分**  
   当前 PU 的 `split_seed` 跟随训练 `seed`，不同训练 seed 会得到不同 target validation/test 样本。正式实验必须拆成独立的 `data_split_seed=24` 和 `train_seed`，所有模型使用完全相同的数据划分。

2. **固定测试 episode**  
   预先生成 1000 个 meta-test episode 的类别、support 和 query 索引清单。所有模型和 seed 使用同一清单，形成配对比较。训练和测试使用两个独立进程，不能让训练阶段消耗的随机数影响测试任务。

3. **目标域不参与选模**  
   当前训练使用目标 validation 准确率保存最佳 checkpoint。工程冒烟测试可以保留这一行为，但正式结果不得使用。模块主实验建议固定训练 500 次 meta-update，保存并测试最终 checkpoint；后续论文实验再增加源域留一验证选模。目标工况只在最终测试阶段打开一次。

4. **统一归一化语义**  
   当前多处使用 BatchNorm，query 批统计可能形成 transductive 评测。工程冒烟测试可沿用当前实现；正式模块排序推荐统一切换到不依赖 query 批统计的 GroupNorm，并让全部 9 个模型重跑。若继续使用当前 BatchNorm，结果必须标记为 `transductive-BN`，不能与 inductive 结果混用。

### 3.3 训练预算解释

当前代码每个所谓 `epoch` 实际只进行一次外循环更新，使用 `meta_batch_size=16` 个 train episode；`tasks_per_epoch=1000` 只保存在采样器中，没有形成 1000 次训练迭代。

因此正式记录统一写为：

```text
500 meta-updates x 16 episodes/update = 8000 train episodes
```

不要再把它解释成“每轮训练 1000 个 task”。

## 5. 核心实验矩阵

LSK 分支采用“GFNet 关/开 × 后接模块无/ARSM/EMA/GCNet”的 `2 x 4` 因子设计，再加 CNN4 锚点，共 9 个配置。

| ID | Backbone | GFNet | ARSM | Attention | 模型简称 | 主要目的 |
|---|---|---:|---:|---|---|---|
| E00 | CNN4 | 否 | 否 | 无 | `CNN4` | 原始骨干锚点 |
| E10 | LSK-lite | 否 | 否 | 无 | `LSK` | 验证 LSK 替换 CNN4 的主效应 |
| E11 | LSK-lite | 是 | 否 | 无 | `LSK-GF` | 验证 GFNet 主效应 |
| E12 | LSK-lite | 否 | 是 | 无 | `LSK-ARSM` | 验证 ARSM 独立主效应 |
| E13 | LSK-lite | 否 | 否 | EMA-lite | `LSK-EMA` | 验证 EMA 独立主效应 |
| E14 | LSK-lite | 否 | 否 | GCNet | `LSK-GC` | 验证 GCNet 独立主效应 |
| E21 | LSK-lite | 是 | 是 | 无 | `LSK-GF-ARSM` | 验证 GFNet 与 ARSM 的协同或冲突 |
| E22 | LSK-lite | 是 | 否 | EMA-lite | `LSK-GF-EMA` | 验证 GFNet 与 EMA 的协同或冲突 |
| E23 | LSK-lite | 是 | 否 | GCNet | `LSK-GF-GC` | 验证 GFNet 与 GCNet 的协同或冲突 |

第一轮不运行 `ARSM+EMA`、`ARSM+GCNet` 或四模块全开。只有两个单模块都通过后，才有理由增加三重组合；否则继续堆叠只会扩大计算量并削弱可解释性。

### 5.1 必须报告的直接对比

| 被验证模块 | 第一直接对比 | 第二直接对比 | 解释 |
|---|---|---|---|
| LSK | E10 - E00 | 无 | 骨干替换贡献 |
| GFNet | E11 - E10 | E21 - E12 | 无后接模块及有 ARSM 时的频域增强贡献 |
| ARSM | E12 - E10 | E21 - E11 | 无 GFNet 及有 GFNet 时的去噪贡献 |
| EMA | E13 - E10 | E22 - E11 | 无 GFNet 及有 GFNet 时的注意力贡献 |
| GCNet | E14 - E10 | E23 - E11 | 无 GFNet 及有 GFNet 时的上下文贡献 |

交互效应示例：

```text
GFNet x ARSM interaction
= (E21 - E11) - (E12 - E10)
```

大于 0 表示组合增益超过两个模块单独效果的简单相加趋势；小于 0 表示存在特征重标定冲突。

## 6. 分阶段执行顺序

### 阶段 A：环境和数据回归检查

1. 运行 Python 语法检查。
2. 检查 PU 5120 张、CWRU 1600 张图片数量和尺寸。
3. 随机抽取 STFT 图确认不是空白、全黑或通道错误。
4. 固定 commit、依赖版本、GPU 型号和 CUDA 版本。
5. 生成数据清单、固定 split 和固定 test episode 清单。

### 阶段 B：双数据集 9 配置工程冒烟测试

PU 和 CWRU 分别对每个 E00-E23 配置执行一次 quick run，共 18 次：

```text
3 meta-updates，meta batch size 4，test episodes 4
```

冒烟通过标准：

- 前向和二阶反向完成；
- loss、梯度和输出均为有限值；
- checkpoint 能保存并由新进程加载；
- predictions、混淆矩阵和训练历史能生成；
- 实际打印的模块开关与 run ID 一致。

quick accuracy 不记录为实验结果。

### 阶段 C：PU 全模块主验证

运行 9 个配置 x 3 个 seed：

```text
9 x 3 = 27 次正式训练
```

全部运行使用 `PU-A9-3S1T-v1`。测试必须在独立进程中加载固定最终 checkpoint，并使用相同的 1000 个 episode。

### 阶段 D：CWRU 全模块跨数据集复核

为直接检验全部现有模块的跨数据集一致性，CWRU 与 PU 使用相同的 E00-E23 九配置矩阵和 seed `3, 24, 38`，不再只从 PU 结果中筛选四个模型。

运行 9 个配置 x 3 个 seed：

```text
9 x 3 = 27 次正式训练
```

如果某模块只在 PU 有效、CWRU 明显退化，应定位为数据集特定模块，不能表述为普遍有效。

### 阶段 E：入选模型深化

只保留综合排名前两名：

- 增加 seed 66、81，形成 5-seed 结果；
- 补充 5-shot；
- 补充 `full_6state`；
- 画 0/1/3/5/10 步适配曲线；
- 对 ARSM 候选模型做固定噪声测试；
- 补充参数量、FLOPs、显存和单 episode 时间。

核心模块验证共 27 次 PU 训练；CWRU 全模块复核增加 27 次，合计 54 次正式训练。双数据集 quick run 共 18 次，最终扩展不计入该数字。

## 7. 指标和统计方法

### 7.1 主指标

| 指标 | 统计方式 |
|---|---|
| Meta-test Accuracy | 每个 seed 在固定 1000 episode 上取均值 |
| Seed Mean ± Std | 3 个训练 seed 的准确率均值和标准差 |
| 95% CI | seed 级结果使用 t 区间；最终候选扩展至 5 seed |
| Macro-F1 | 汇总映射回原语义类别的 query 预测后计算 |
| Per-class Recall | 与归一化混淆矩阵同时报告 |
| Paired delta | 在完全相同 test episode 上计算模块与直接父模型的准确率差 |

固定 episode 上的配对 bootstrap 可作为补充，但模型 seed 的均值和方差是主要证据，不能只用 1000 个 episode 产生很窄的区间来替代多 seed 训练。

### 7.2 效率与稳定性指标

- 总参数量和新增参数比例；
- FLOPs 或 MACs；
- 每次 meta-update 平均耗时；
- 单个 test episode 平均耗时；
- 峰值 GPU 显存；
- 外循环梯度范数中位数和 95 分位数；
- 非有限梯度、跳过 optimizer step 和 NaN 次数；
- 最终 50 次 meta-update 的 loss/accuracy 波动。

## 8. 模块保留判定

### 8.1 通用判定

一个模块进入后续主线，至少满足：

1. 相对直接父模型的 3-seed 平均准确率提升不低于 `0.5 pp`；
2. 至少 2/3 seed 为正提升，且任一 seed 不出现超过 `1.0 pp` 的明显退化；
3. 不增加 NaN、非有限梯度或训练失败；
4. 标准差不比父模型增加超过 25%；
5. 参数和时间开销与“lite”定位一致；
6. CWRU 上方向一致，或能给出明确的数据集特定原因。

`0.5 pp` 是项目筛选阈值，不是统计显著性的替代。最终论文结论仍以多 seed 区间和配对差异为准。

### 8.2 模块特定判定

| 模块 | 额外条件 |
|---|---|
| LSK-lite | E10 应稳定优于 E00，并报告参数和速度代价 |
| GFNet-lite | E11 优于 E10，且频域分支不引起梯度尖峰或明显减速 |
| ARSM | 干净数据提升不足 `0.5 pp` 时，若 0/-2 dB 平均提升至少 `1.0 pp`，可改定位为鲁棒性模块；新增参数建议不超过父模型 5% |
| EMA-lite | 历史结果曾下降，只有 E13/E22 多 seed 均改善才保留，否则作为负消融 |
| GCNet | 历史结果曾下降，只有 E14/E23 多 seed 均改善才保留，否则作为负消融 |

## 11. 最终决策规则

```text
工程冒烟失败
  -> 修复实现，不进入正式训练

PU 单模块无稳定提升
  -> 不进入组合主线，保留负结果

PU 有效但 CWRU 无效
  -> 标记为数据集特定，不主张普适性

PU 与 CWRU 均有效
  -> 扩展至 5 seed、5-shot 和效率测试

ARSM 仅在噪声下有效
  -> 定位为鲁棒性模块，而不是干净数据精度模块
```

本轮结束时应能得到一条精简、证据明确的主线，而不是默认把全部模块继续串联。
